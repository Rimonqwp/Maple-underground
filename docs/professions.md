# 主世界农业与挖矿

## 安装与入口

用 `build-all.cmd` 构建，更新 `dist/` 中的 `underground_state`、`underground_item`、`underground_collect`；其余模块仍按原依赖顺序构建。本功能不修改岛屿或 OneBlock 模块。

主插件首次启动创建 `plugins/underground_state/professions.yml`。`enabled-worlds` 空列表表示启动时的服务器主世界；填写世界名称可指定多个生存世界。职业装备的附加属性、专业增产和职业事件在白名单内生效。工具、武器的技能等级限制一直生效。

农业／挖矿技能详情菜单的第 47 格提供职业装备图鉴，也可使用：

- `/profession farming`、`/profession mining`：装备图鉴、材料与制作条件。
- `/profession register`：登记背包、穿戴与副手中的职业装备，不消耗物品。
- `/profession give <物品ID> [玩家]`：管理测试命令，需要 `underground_item.profession.admin`，默认仅 OP；输入第二参数时支持补全。

装备图鉴中选择套装，再选择单件，能查看九宫格材料和个人门槛。“选择此合成配方”后在原版合成台制作。相同材料的可选套装也通过此按钮区分。九合一原料存在原版方块配方时，默认保留原版产物，选择职业压缩配方才输出压缩材料。选择持续到更换配方或退出。

装备、工具和武器每次只制作一件，使用普通左／右键取出；压缩材料可 Shift 批量制作。输出容量不足时不消耗材料。自动合成器只能制作身份完全匹配且没有个人门槛的压缩材料，不能制作装备、工具或武器；职业物品不能通过锻造台绕过升级链。升级保留自定义名字和适用于新物品、合法且互不冲突的附魔。

## 配置与职责

`underground_item/src/main/resources/professions.yml` 是配置源：32 套、128 件四部位装备，12 个工具、6 个武器、48 个压缩原料和 12 个事件材料，合计 206 个唯一物品。内容使用 YAML 支持的 JSON 格式，启动时复制至插件数据目录；之后不会覆盖管理员现有配置，修改后重启生效。

`python tools/generate_professions.py` 可按本次方案重新生成资源配置。`python tools/simulate_professions.py` 使用经验表与资源配置重新生成 [平衡报告](profession-balance.md)。生成器与报告工具仅在开发时运行，服务端不需要 Python。

- `underground_state.professions`：职业加成接口、采集完成事件、采集经验与收藏结算、放置来源、计数和图鉴存档。
- `underground_item.professions`：统一物品目录、四件套判定、合成验证、职业武器、事件怪物与图鉴界面。
- `underground_collect`：引用主插件的统一收藏阈值和经验奖励，农业／挖矿扩展至 XII，其他收藏保持 IX。

专业经验字段与原有附魔经验加成字段分开。每次手动采集锁定工具、装备加成及采集前等级；普通增产不重复奖励技能经验。时运替换为职业幸运统一计算；精准采集保留自然矿石经验，关闭矿物增产、稀有材料与收藏。

甘蔗、仙人掌、竹子连锁收割逐段检查权限和放置来源，只给自然生长段结算；整次手动操作只抽一次稀有和职业事件。上方权限检查被拒绝时取消整次收割。T3 起农业工具复种使用背包中的实际种植材料，并触发区域插件可取消的放置事件；没有材料不复种。成熟度检测、被取消的掉落、自动掉落、玩家放置矿物、活塞搬运均进入同一条防重复结算路径。

职业事件具有独立普通／精英冷却；已有活动事件时停止抽取。召唤失败保留保底且不启动冷却。精英完整核心概率锁定召唤时的稀有加成，随后换装不改变它。怪物使用独立的 400／6,000 生命账本和 20／80 防御；原版实体生命只负责受击反馈。职业护甲减伤先于玩家现有防御公式应用。普通／精英基础攻击为 12／35，精英每 8 秒提示、1.5 秒后对 3 格内触发者发动基础伤害 70 的攻击。

只允许触发者成为怪物目标。其他玩家可贡献伤害，但材料和个人挑战只结算给伤害贡献不少于 20%、击败时在 24 格内的触发者。事件超时、死亡、退出、离开 24 格累计连续 10 秒时清理，不发奖励。不掉落原版经验或战利品，不破坏方块。

## 存档与兼容

所有职业 MySQL 访问经 `MySqlConnectionFactory.connect()` 使用 `state` 数据源。启动时只创建缺失的表：

- `player_profession_progress`：UUID＋进度键唯一，保存万分之一经验余数、最高领奖等级、挑战、各类保底和冷却时间。
- `player_profession_equipment_collection`：UUID＋物品 ID 唯一，记录装备登记时间。

旧经验十分之一余数只迁移一次。职业升级金币和属性奖励按最高已领奖等级计算，降级再升级不会重复发放；首次处理旧玩家时，以原经验对应等级建立领奖基线。旧收藏数量、已领奖状态和测试物品保留，不删除或重置数据库。既有基础属性不做强制重算，今后新增技能等级每级奖励幸运 2。

图鉴登记存于独立表；收齐五套／十套副装备的徽记由已登记四部位集合计算，不提供任何属性、经验或配方权限。装备与材料可以交易，制作门槛仍检查制作者自己的等级、收藏和挑战。

## 自动验证与实服验收

`build-all.cmd` 按 Paper 26.3、Java 25 编译所有八个模块。三个相关模块使用 Maven `test` 运行测试。仓库原先的 MockBukkit 4.116.1 在清单中指定 Paper 26.2，直接用 26.3 运行会因新注册表 `decorated_pot_pattern` 不匹配而初始化失败。Surefire 因此只在模拟测试运行时使用它声明的 `26.2.build.111-stable`；生产编译与产物仍为 26.3。MockBukkit 的工作台第十个矩阵槽缺陷在合成测试夹具中按 Bukkit 九格契约修正。

测试涵盖整套属性、单职业混搭、最低事件资格、技能等级限制、相对概率及上限、固定精度经验、原 60 级曲线、X–XII 收藏、配方身份、门槛、附魔继承、合成容量及单次消费、批量压缩、成熟与右键采集、取消掉落、时运／精准采集、连锁采集、区域拒绝、活塞标记、采集快照和不消耗的图鉴登记。存档测试使用真实 SQLite JDBC 文件及两条 MySQL upsert 的等价语法，检验重载后的余数、保底、冷却、挑战、最高领奖等级和唯一登记；它不代替 MySQL 实服验收。

当前工作区没有正在运行的主世界 Paper 测试服。以下项目须在配好 `state` 数据源的 Paper 26.3 测试服继续验证，不能视为已经实测：

1. 使用现有区域保护插件拒绝成熟收割、上方连锁作物和复种位置，确认无额外产物、经验、收藏、事件或种子消耗。
2. 主世界以外禁用职业附加效果；成熟／右键／连锁采集、活塞、自动农场、重捡和交易逐项核对。
3. 按配方完整走通农业和挖矿 T1–T6、三阶武器和五条低／高副分支，核对相同材料配方选择与原版方块配方。
4. 普通、精英召唤、目标限制、伤害和范围预警、贡献不足、离开／退出／死亡／超时，及区域插件拒绝生成位置。
5. 召唤后换稀有装备核对完整核心概率不重算；关闭服务器再启动，核对保底、余数、挑战、图鉴和最高领奖等级。
6. 使用实际采集日志校准小时经验、稀有产量、普通／精英事件频率与探索时间，检查 150–200 小时目标及市场交易对材料瓶颈的影响。
